# OpenDMA User Guide

This guide describes how to integrate and operate `odma_core` in Direct Register Mode (DR mode, phase a) and in
Scatter/Gather Mode (SG mode, phase b). The register map, the register fields, the descriptor format and the
programming sequences are those of \[PG021\] (AMD AXI DMA product guide,
version 7.1); this guide states where OpenDMA implements, interprets or omits a part of it. The register map with all
fields is [hdl/odma_registers/docs/register_map.md](../hdl/odma_registers/docs/register_map.md), the C header
`sw/odma_regs.h`.

## 1. Sources

The synthesis sources are listed in `compile_order.txt` (generated by `python run.py --compile-order`) in compile
order. The Open Logic sources go into the VHDL library `olo`, the OpenDMA sources into the library `opendma`; the
top level is `opendma.odma_core`. Open Logic is the submodule `open-logic/` (open-space-hdl/open-logic-ft, tag
4.7.0-ft.8). All sources are VHDL-2008.

An inconsistent configuration stops the elaboration with a message that names the generic. The defaults of
`IncludeSg_g` and `StsCntrlStrm_g` differ from \[PG021\] (architecture section 6): a configuration taken from a
system with the vendor core sets them explicitly. Bursts never cross 4 KB, so a channel with a wide memory issues
bursts of at most 4096 bytes whatever the burst generic is (32 beats of 1024 bits). The verification report of
`odma_core` lists the simulated and the synthesised values of every generic.

## 3. Clock and reset

All ports belong to `Clk`, the synchronous configuration of \[PG021\]; the core has no clock domain crossing. A
system with other stream or memory clocks places `olo_ft_fifo_async` (with `SyncTmr_g` = true) at the ports. `Rst`
is synchronous and high-active and resets the whole core. A soft reset (section 5.4) resets the channels and the
registers but not the AXI4-Lite slave, so that the register access that starts it completes.

## 4. Interfaces

| Interface | Ports | Content |
| --- | --- | --- |
| Register port | `S_AxiLite_*` | AXI4-Lite slave, 10 address bits, 32 data bits. Every access gets OKAY; a write uses all 32 bits whatever `WStrb` holds; offsets without a register read 0 |
| MM2S memory port | `M_AxiMm2s_Ar*`, `M_AxiMm2s_R*` | AXI4 read master: INCR bursts of full-width beats (FIXED bursts of at most 16 beats for keyhole), `ArCache` 0011, `ArProt` 000, no ID signals; up to 8 bursts outstanding |
| MM2S stream | `M_Mm2s_Data`, `_Keep`, `_Last`, `_Valid`, `_Ready` | AXI4-Stream master: one packet per transfer, first byte in lane 0, `TKeep` contiguous from lane 0 in the last beat |
| S2MM stream | `S_S2mm_Data`, `_Keep`, `_Last`, `_Valid`, `_Ready` | AXI4-Stream slave: packets of any length; the bytes of the last beat are those up to the first lane whose `TKeep` bit is clear; `TKeep` of the other beats is not used |
| S2MM memory port | `M_AxiS2mm_Aw*`, `M_AxiS2mm_W*`, `M_AxiS2mm_B*` | AXI4 write master: INCR bursts with write strobes (FIXED bursts of at most 16 beats for keyhole), `AwCache` 0011, `AwProt` 000, no ID signals; a burst is requested only when all its data is in the core |
| Descriptor port | `M_AxiSg_Ar*`, `M_AxiSg_R*`, `M_AxiSg_Aw*`, `M_AxiSg_W*`, `M_AxiSg_B*` | SG mode only: AXI4 master with `AddrWidth_g` address bits and 32 data bits for the descriptors of both channels. A fetch is one INCR burst of 8 beats (descriptor words 0x00 to 0x1C), a status write one beat at descriptor offset 0x1C with all strobes; `AxSize` 4 bytes, `AxCache` 0011, `AxProt` 000, no ID signals; at most one fetch and one status write at a time, the channels served round robin. In DR mode the port is idle and its inputs may stay open |
| Interrupts | `Mm2s_Irq`, `S2mm_Irq` | Level, high-active: the OR of the enabled `IOC_Irq`, `Dly_Irq` (SG mode) and `Err_Irq` flags of the channel |
| ECC interrupt | `Ecc_Irq` | Level, high-active: an enabled flag of `ECC_STATUS` (extension window) |
| Reset outputs | `Mm2s_RstOut`, `S2mm_RstOut` | High-active, during `Rst` and during a soft reset: reset of the stream peers |

The ports of a channel that the configuration does not include keep constant idle values (valid and ready outputs
'0', burst type INCR, cache 0011, all other outputs 0), and its inputs may stay open. The same holds for the
descriptor port in DR mode, whose `AxSize` outputs read 4 bytes.

## 5. Programming sequence

### 5.1 MM2S transfer

1. Write `MM2S_DMACR` with `RS` = 1 and, for completion by interrupt, `IOC_IrqEn` and `Err_IrqEn`.
2. Poll `MM2S_DMASR` until `Halted` reads 0.
3. Write the buffer address to `MM2S_SA`, with more than 32 address bits also the upper part to `MM2S_SA_MSB`.
4. Write the length in bytes to `MM2S_LENGTH`; this write starts the transfer.
5. Wait for `Mm2s_Irq` or poll until `MM2S_DMASR.Idle` reads 1.
6. Clear `IOC_Irq` by writing 1 to it in `MM2S_DMASR`.

The buffer is sent as one packet. Steps 3 to 6 repeat for every transfer while the channel runs.

### 5.2 S2MM transfer

The same steps with `S2MM_DMACR`, `S2MM_DMASR`, `S2MM_DA`, `S2MM_DA_MSB` and `S2MM_LENGTH`; the length is the size
of the buffer. After the completion `S2MM_LENGTH` reads the number of bytes of the received packet. The channel takes
stream data only while it runs; a packet that arrives before its transfer is programmed waits in the data buffer.

### 5.3 Halt

Writing `RS` = 0 halts a channel; `DMASR.Halted` reads 1 once it has stopped. A transfer in progress is completed:
MM2S sends it to its end; S2MM writes the chunks of the packet that are complete in its buffer, discards the rest of
the packet up to its `TLast` and does not report the completion (interpretation I8 of `odma_registers`). A packet
whose `TLast` the stream port accepted before the halt is written completely. `Halted` does not wait for the `TLast`
of the discarded rest: the channel keeps dropping its beats while halted, also when the stream peer never ends the
packet, and a soft reset ends that discard. A following start resumes the channel with the next programmed transfer.

### 5.4 Errors and soft reset

An error halts its channel: `DMASR` shows the error flag and `Err_Irq`, `DMACR.RS` reads 0, and `DMASR.Halted`
follows when the channel has shut down, a few clock cycles after the interrupt. After an error, software waits for
`Halted`, reads the flags and resets the core: it writes `DMACR.Reset` = 1 of either channel and polls until `Reset`
reads 0. The other channel keeps working until the reset.

| Error | Flags |
| --- | --- |
| Read response SLVERR or DECERR (MM2S); the packet is still sent completely | `MM2S_DMASR.DMASlvErr` or `DMADecErr` |
| Write response SLVERR or DECERR (S2MM); no further write for the packet, the rest of the packet is discarded up to `TLast` | `S2MM_DMASR.DMASlvErr` or `DMADecErr`, and `DMAIntErr` |
| EXOKAY response (OpenDMA never requests exclusive access; interpretation I14) | as SLVERR |
| Buffer beyond the top of the address space: no memory access, no stream data | `DMADecErr` (S2MM also `DMAIntErr`) |
| S2MM packet longer than the buffer: the bytes that fit are written, nothing beyond the buffer, the rest discarded up to `TLast` | `S2MM_DMASR.DMAIntErr` |

The soft reset resets both channels. It stops them at once, completes every AXI transaction the memory has accepted
(read data is discarded, write data of accepted bursts is written), takes no S2MM stream data and holds both reset
outputs high; the stream peers connected to them abandon their packets. Then the registers return to their reset
values, and an error injection pending in an FT buffer is cancelled.

### 5.5 Scatter/Gather Mode

With `IncludeSg_g` the channels take their transfers from descriptor chains in memory (\[PG021\], descriptors of
Tables 25 to 40, programming sequence of chapter 4). The registers of DR mode (`MM2S_SA`, `MM2S_LENGTH`, `S2MM_DA`,
`S2MM_LENGTH`) are replaced by `CURDESC`, `TAILDESC` and their MSB registers; `DMASR.SGIncld` reads 1.

Descriptors and chains:

- A descriptor is 16 words aligned to 64 bytes; the engine reads words 0x00 to 0x1C (`NXTDESC`, `NXTDESC_MSB`,
  `BUFFER_ADDRESS`, `BUFFER_ADDRESS_MSB`, two reserved words, `CONTROL`, `STATUS`) and writes only the `STATUS`
  word. The user application words follow with the control and status streams of phase c.
- A chain is linked by `NXTDESC`; the last descriptor normally points back to the first, as the drivers build their
  rings. Software clears `Cmplt` in the `STATUS` word of every descriptor it hands to the engine.
- Buffers lie at any byte address, also across 4 KB boundaries, with lengths from 1 to 2**`LengthWidth_g` - 1.
- MM2S: a packet consists of the buffers of the descriptors from one with `TXSOF` to the next with `TXEOF`; the
  stream carries their bytes without gaps, with `TLast` only on the last beat. A descriptor without `TXSOF` after
  one with `TXEOF` starts a new packet anyway (interpretation SGI-03 of `odma_sg`).
- S2MM: a packet fills the buffers of the chain in order and continues at byte 0 of the next buffer; the status of
  the first buffer of a packet has `RXSOF`, that of the last `RXEOF`, and the transferred bytes of each buffer. A
  packet without bytes (only a last beat without valid bytes) gives one status with 0 bytes and both flags
  (interpretation SGI-13). When the chain has no further descriptor before the tail, the rest of the packet waits at
  the stream input (`TReady` low) until the tail pointer is moved.

Programming sequence of each channel:

1. Write the address of the first descriptor to `CURDESC` (above 32 address bits also `CURDESC_MSB`) while the
   channel is halted.
2. Write `DMACR` with `RS` = 1, the interrupt enables and, as needed, `IRQThreshold`, `IRQDelay` and `CyclicBD`.
3. Poll `DMASR` until `Halted` reads 0.
4. Write the address of the last prepared descriptor to `TAILDESC`. This write starts the engine; above 32 address
   bits write `TAILDESC` first and `TAILDESC_MSB` last, which starts it (interpretation SGI-01 of `odma_sg`), as the
   public drivers do.
5. The engine fetches the descriptors up to the tail, transfers their buffers and writes their status: transferred
   bytes, the error flags, S2MM `RXSOF` and `RXEOF`, and `Cmplt` = 1 after a transfer without error. It fetches one
   descriptor ahead, so consecutive transfers follow each other without waiting for a fetch.
6. After the tail descriptor the engine stops and `DMASR.Idle` reads 1; `CURDESC` reads the tail. Software processes
   the completed descriptors, clears their status and moves the tail pointer, also while the engine still works.

Interrupts: every completed packet counts down the threshold counter; when it reaches 0, `IOC_Irq` is set and the
counter is reloaded with `IRQThreshold`. The status words of a packet are in memory before its interrupt flag is set.
With `IRQDelay` not 0, a packet completion that does not reach the threshold starts the delay timer (units of 125
clock cycles); the first stream beat of the next packet stops and clears it, and when it expires `Dly_Irq` is set and
the threshold counter reloaded. An MM2S packet can start before the completion of the packet before it, because the
engine issues the next descriptor ahead: the timer then runs during that packet, and `Dly_Irq` can be set while it is
being sent (interpretation R10 of `odma_registers`).

Cyclic mode (`DMACR.CyclicBD` = 1): after the first tail pointer write the engine processes the ring until the
channel is halted or reset, ignores `Cmplt` of the fetched descriptors and the tail pointer, and still writes the
status of every descriptor.

Halt (`RS` = 0): the engine issues no further descriptor, the channel ends the transfer in progress as in DR mode,
and its status is written; descriptors fetched but not started keep their status, and `CURDESC` points to the first
of them. `DMASR.Halted` is set when the channel and the engine have both stopped.

Errors: each halts its channel with `Err_Irq`, and `CURDESC` points to the descriptor of the error. The descriptors
before it are completed with their status; an MM2S descriptor after it may also be completed, because it was already
issued (interpretation SGI-08 of `odma_sg`).

| Error | Flags |
| --- | --- |
| Descriptor fetch or status write answered with SLVERR (or EXOKAY) or DECERR | `SGSlvErr` or `SGDecErr` |
| Stale descriptor: `Cmplt` = 1 at the fetch outside cyclic mode; the descriptor is not processed and not written | `SGIntErr` |
| Buffer length 0: no transfer, the status gets `DMAIntErr` and `Cmplt` 0 | `DMAIntErr` |
| Transfer error of the channel (section 5.4): the status gets the flag and `Cmplt` 0 | `DMASlvErr`, `DMADecErr` (S2MM also `DMAIntErr`) |

Recovery is the soft reset of section 5.4; in SG mode it also completes every descriptor access the memory has
accepted. A halt or an error inside an MM2S packet of several descriptors ends the packet on the stream: `TLast` comes
with the last byte of the last descriptor the channel had accepted, before `DMASR.Halted` is set (interpretation M4
of `odma_mm2s`). An S2MM packet whose `TLast` the stream port accepted before the halt and whose bytes fit into the
buffer of the current descriptor is written completely, with `RXEOF` in its status. A packet that needs a further
buffer is cut like a packet still arriving: the bytes of its complete chunks stay in memory, the rest is discarded
up to its `TLast`, and the last written status has no `RXEOF` (interpretation SGI-11 of `odma_sg`, `odma_s2mm`
S2-HA-01).

Keyhole (`DMACR.Keyhole` = 1, for FIFO-like peripherals at a fixed address): the transfers use FIXED bursts of at
most 16 beats at the buffer address with the bits below the memory data width cleared, so every beat accesses the
same memory word. MM2S takes the setting in SG mode only (\[PG021\] Table 6 gives the bit no function in DR mode,
interpretation I1); S2MM in both modes, taken at the start of each transfer. The stream bytes are packed from lane 0
as for an incrementing transfer of the same length; a buffer address that is not aligned to the memory width is
used with its low bits cleared.

### 5.6 Extension window

With `ExtRegs_g` the offsets 0x100 to 0x1FF hold an identification word (`EXT_ID` = 0x4F444D41), the version, the
values of all generics, the ECC counters of the FT buffers, their flags with the enables of `Ecc_Irq` and an error
injection (register map). The FT buffer indices are 0 MM2S read data, 1 S2MM data, 2 S2MM chunk, 3 S2MM write
data, 4 MM2S transfer and 5 MM2S response; in SG mode 6 MM2S descriptor buffer, 7 S2MM descriptor buffer, 8 read
data and 9 write data of the descriptor port. The other indices count nothing. Software written for \[PG021\] does
not access the window.

`ECC_INJECT` flips one bit (single error) or two bits (double error) of the next word written to the selected
buffer, in one of two modes:

| `ECC_INJECT.Data` | Bits flipped | Effect |
| --- | --- | --- |
| 0 (after every reset) | Parity bits of the code | The data never changes: a single error is corrected, a double error is detected and counted. Safe in a running system |
| 1 | Data bits 0 and 1 | A single error is corrected (data unchanged). A double error corrupts the word: a byte of the MM2S stream (index 0), of the S2MM packet in memory (indices 1 and 3), the length of the MM2S packet (index 4), the result code of the MM2S transfer (index 5, `DMADecErr`), the length of an S2MM chunk (index 2), the buffer length of a descriptor (indices 6 and 7), the `NXTDESC` bits 1 and 0 of a fetch, which the engine ignores (index 8), or the transferred bytes of a status word (index 9). For tests only |

## 6. Protection scope

The core is designed for radiation environments together with the triple modular redundancy (TMR) of the synthesis
tool, like the Open Logic ft entities it is built on. It protects the parts in the first rows itself and relies on
TMR for all other logic:

| Part | Protection | Indication and test |
| --- | --- | --- |
| The FT buffers: MM2S read data, transfer and response buffers; S2MM data, chunk and write data buffers; in SG mode the descriptor buffers of both channels and the read and write data buffers of the descriptor port | SECDED ECC of the Open Logic ft entities: a single error is corrected, a double error is detected and counted; the word of a double error is passed on as read (corrupted data, length, result code or descriptor field of the transfer it belongs to), and the core does not turn the double error into a transfer error | `ECC_COUNT_0` to `ECC_COUNT_9`, `ECC_STATUS`, `Ecc_Irq` with `ECC_ENABLE`; error injection through `ECC_INJECT` (parity mode non-destructive, data mode corrupts data with a double error, section 5.6) |
| Clock domain crossings and reset synchronisers | The core has none (one clock domain); an `olo_ft_fifo_async` placed at a port by the integrator uses triplicated synchronisers (`SyncTmr_g` = true) | none |
| State machines | Recovery state through the `when others` branch and the reset | none |
| All other logic: registers of the control and data paths, counters, pointers, pipeline registers | TMR of the synthesis tool (for example `syn_radhardlevel` = `tmr` with Synplify, or the equivalent setting of the tool chain). The core adds no protection of its own for this logic; without TMR, an upset in it is not covered | synthesis report |

The integrator:

- enables the TMR of the synthesis tool for the core and the logic around it,
- checks in the synthesis report that TMR was applied, that the synchroniser chains of the crossings were not
  triplicated a second time, and that no register-based storage meant to be protected by TMR was inferred as a RAM
  primitive,
- requests safe state machines, so that synthesis keeps the `when others` branches (AMD Vivado: property
  `FSM_SAFE_STATE` = `default_state` on the state registers; Synplify: attribute `syn_encoding` = `safe`),
- protects the configuration memory of SRAM-based FPGAs by scrubbing; this is part of the FPGA design, not of the
  core.

The ECC paths are verified in simulation by error injection. Whether the protection as a whole meets the
requirements of a mission is shown by a radiation test with the core in operation (TRL 5).

## 7. Performance

MM2S sends one stream beat per clock cycle when a burst has at least 8 stream beats (burst beats x memory width /
stream width) and the memory and the stream peer are ready; with fewer, the read latency of the memory is not hidden.
S2MM issues one write command per chunk of one burst, and the write master accepts the next command about 7 clock
cycles after the data of the previous one. With equal memory and stream widths a chunk of C stream beats therefore
takes about C + 7 clock cycles; with a memory at least four times as wide as the stream the channel takes one beat
per clock cycle. Measured with an always ready memory and a stream without gaps (verification reports of the
channels):

| Memory / stream width, burst beats | MM2S beats per clock cycle | S2MM beats per clock cycle |
| --- | --- | --- |
| 32 / 32 bits, 16 beats (the defaults) | 1.0 | 0.76 |
| 128 / 64 bits, 32 beats | 1.0 | 0.95 |
| 256 / 128 bits, 4 beats | 1.0 | 0.51 |
| 512 / 256 bits, 8 beats | 1.0 | 0.70 |
| 512 / 512 bits, 2 beats | 0.51 | 0.24 |
| Memory four or more times the stream width | 1.0 | 1.0 |

Short bursts at equal widths cost the most: a system that needs the full S2MM rate with equal widths chooses long
bursts (`S2mmBurstBeats_g` 64 or more gives at least 0.9 beats per clock cycle) or a wider memory port. A transfer
takes at least four clock cycles in the AXI master for its command, and the register accesses of DR mode add the
time of the processor for every transfer.

In SG mode the engine processes at most one descriptor per fetch time: about 22 clock cycles per descriptor for one
channel and 40 per channel when both work, with a descriptor memory without latency; a latency of L clock cycles
adds about L per descriptor for one channel and 2 x L per channel for two (verification report of `odma_sg`). Buffers
that take longer to transfer than a fetch follow each other without a gap on the stream; a chain of many short
buffers runs at the descriptor rate.

An S2MM packet over several buffers waits at every buffer boundary inside the packet: the channel takes the next
buffer only after the data of the full one is written and its write responses have arrived, and the stream input
pauses until then. At the boundary the write master runs empty, and it waits until the first chunk of the next
buffer is complete and has reached it. Stages from the last write beat of the full buffer, measured in the core bench
(TC-CO-20) with a write response latency of L clock cycles:

| Stage | 32 / 32 bits, 16 beats (the defaults) | 512 / 256 bits, 4 beats |
| --- | --- | --- |
| Write response of the last burst | 1 + L | 1 + L |
| Result accepted by the Scatter/Gather engine | 4 + L | 4 + L |
| Next command accepted (the engine holds the next descriptor; its status write and the next fetch run meanwhile) | 5 + L | 5 + L |
| First stream beat of the next buffer taken by the split | 6 + L | 6 + L |
| First chunk of the next buffer complete | 22 + L | 14 + L |
| Its write command at the write master | 25 + L | 17 + L |
| First write beat (the master starts a burst when all its data is buffered) | 51 + L | 37 + L |

Between two bursts inside a buffer the master pauses for 7 (defaults) or 11 (512 / 256 bits) clock cycles, so a
buffer boundary costs 43 + L and 25 + L clock cycles. Measured with packets of 16 KB, a stream without gaps and a
memory that is always ready apart from the write response latency:

| Memory / stream width, burst beats | Write response latency | Pause per buffer boundary | Beats per clock cycle, 1 KB buffers | Beats per clock cycle, 4 KB buffers | Beats per clock cycle, 4 KB buffers at unaligned addresses |
| --- | --- | --- | --- | --- | --- |
| 32 / 32 bits, 16 beats (the defaults) | 0 | 43 clock cycles | 0.63 | 0.69 | 0.59 |
| 32 / 32 bits, 16 beats (the defaults) | 50 | 93 clock cycles | 0.56 | 0.67 | 0.57 |
| 512 / 256 bits, 4 beats | 0 | 25 clock cycles | 0.36 | 0.46 | 0.38 |
| 512 / 256 bits, 4 beats | 50 | 75 clock cycles | 0.23 | 0.39 | 0.34 |

Packets that fit into one buffer do not pause; buffers of several KB keep the loss small. A buffer address that is
not a multiple of the memory word costs time in both modes: a chunk then covers one memory word more than a burst
holds and is written as two bursts. That adds 62 clock cycles per KB with the defaults, 14 with 512 / 256 bits and
240 with 64 / 8 bits and 2-beat bursts (TC-CO-20). Buffers at multiples of the burst size avoid it. The MM2S join of
several buffers costs at most one clock cycle per packet.

## 8. Integration constraints

| Constraint | Reason |
| --- | --- |
| TMR of the synthesis tool enabled for the core | The core protects its FT buffers itself and relies on TMR for all other logic (section 6) |
| The memory answers every burst in order (no ID signals) | The masters use one ID for all transactions |
| The stream peers are reset by `Mm2s_RstOut` and `S2mm_RstOut` | A soft reset ends the packets in progress; a peer that continues a packet sends its rest as a new packet |
| One clock for all ports | Synchronous configuration; asynchronous stream or memory clocks need FIFOs at the ports (section 3) |
| `StsCntrlStrm_g`, `UseRxLength_g` and `MicroDma_g` false | The control and status streams and the micro DMA follow in phase c |
| Keyhole buffers aligned to the memory data width | The address bits below the memory width are ignored for FIXED bursts |
| SG mode: the descriptor memory answers in order (no ID signals) and holds descriptors aligned to 64 bytes | The descriptor port uses one ID; bits 5 to 0 of the descriptor pointers are ignored |

## 9. Conformance

Implemented (\[PG021\] references in the compliance matrix, [docs/compliance.md](compliance.md)):

- Register map and fields of DR mode, the programming sequences of DR mode for both channels, the halt, the soft
  reset, the interrupt outputs and their enables, the reset outputs.
- Transfers at any byte address and of any length up to 2**`LengthWidth_g` - 1 bytes in every width configuration
  (the function of the data realignment engine, also for streams wider than 512 bits), 4 KB and burst splitting.
- The configuration generics of Table 44 listed in section 2, with the ranges of \[PG021\].
- Scatter/Gather Mode: the register map with `CURDESC` and `TAILDESC`, the descriptors without user application
  fields, the tail pointer mode, cyclic mode, interrupt coalescing with the threshold and the delay timer, the
  errors of the engine, packets of one or several descriptors in both channels.
- Keyhole transfers with FIXED bursts (MM2S in SG mode, S2MM in both modes, interpretation I1).
- `DMASlvErr` and `DMADecErr` (`SGSlvErr` and `SGDecErr` for descriptor accesses) from the response codes of the
  memory.

Not implemented: control and status streams with the user application fields, the receive length in the status
stream, micro DMA (phase c). Not in scope: multichannel mode and the asynchronous clock configuration.

## 10. Verification and tools

Each module has a specification, an architecture, a verification plan and a verification report in
`hdl/<module>/docs/`. The core tests (`odma_core`) execute the programming sequences of a model written from
\[PG021\] against the assembled core in seven DR and five SG configurations. `python run.py` runs the full
regression with GHDL, `python lint/synth_check.py` the synthesis check of the generics,
`python tools/compliance.py --check` the traceability to \[PG021\]. The technology readiness level is stated in the
README and the roadmap.
